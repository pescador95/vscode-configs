# Technical Documentation Rules

## Technical Perspective

Technical documentation describes how the system is implemented and operated.

Document applicable:

* architecture;
* modules and components;
* domain boundaries;
* APIs and contracts;
* data models;
* database schemas;
* authentication and authorization;
* integrations;
* messaging;
* caching;
* configuration;
* infrastructure;
* deployment;
* observability;
* error handling;
* technical constraints;
* architectural decisions.

## Evidence

Technical documentation must be derived from actual source code, configuration, infrastructure definitions, tests, and established technical documentation.

Do not document hypothetical architecture or implementation.

## Accuracy

Document actual responsibilities, dependencies, data flow, contracts, configuration, and operational behavior.

Do not infer undocumented behavior from naming alone.

## Consistency

Follow the project's existing technical terminology, architecture, structure, and documentation conventions.

When implementation and documentation diverge, verify the intended behavior before updating either source.
